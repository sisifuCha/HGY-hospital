# 敏感操作和黑名单检测功能实现总结

## 一、功能概述

实现了完整的敏感操作检测和黑名单管理系统，用于防止患者恶意退号行为。系统包含5大核心功能：

### 核心规则
1. **敏感操作定义**：患者在就诊开始前3小时内退号视为敏感操作
2. **统一倒计时**：患者每次产生敏感操作时，所有历史敏感操作时间统一更新为当前时间
3. **黑名单触发**：累计3次敏感操作后自动加入黑名单
4. **权限限制**：黑名单患者无法进行挂号、候补、加号操作
5. **自动清理**：20天后自动清理敏感操作记录和黑名单状态

## 二、数据库设计

### 1. sensitive_operation 表（敏感操作记录）
```sql
CREATE TABLE sensitive_operation (
    id VARCHAR(10) PRIMARY KEY,           -- SEN0001, SEN0002...
    patient_id VARCHAR(10) NOT NULL,      -- 患者ID
    sensitive_op_type VARCHAR(50) NOT NULL, -- 操作类型
    op_time TIMESTAMP NOT NULL,           -- 操作时间（统一更新）
    remark TEXT                           -- 备注信息
);
```

**关键字段说明**：
- `op_time`：所有该患者的记录会统一更新为最新操作时间，实现"统一倒计时"
- 外键关联 `patient.id`，级联删除

### 2. blacklist 表（黑名单）
```sql
CREATE TABLE blacklist (
    id VARCHAR(10) PRIMARY KEY,           -- BL0001, BL0002...
    sen_id1 VARCHAR(10) NOT NULL,         -- 第1条敏感操作ID
    sen_id2 VARCHAR(10) NOT NULL,         -- 第2条敏感操作ID
    sen_id3 VARCHAR(10) NOT NULL,         -- 第3条敏感操作ID
    count SMALLINT NOT NULL DEFAULT 3     -- 违规次数（≥3）
);
```

**设计亮点**：
- 记录触发黑名单的3条敏感操作ID，便于追溯
- 外键关联 `sensitive_operation.id`，级联删除
- 约束条件：`count >= 3`

### 3. 视图 v_blacklist_patients（黑名单查询视图）
```sql
CREATE VIEW v_blacklist_patients AS
SELECT 
    so1.patient_id,
    p.name AS patient_name,
    b.count AS violation_count,
    so1.op_time AS latest_op_time,
    so1.op_time + INTERVAL '20 days' AS release_time
FROM blacklist b
JOIN sensitive_operation so1 ON b.sen_id1 = so1.id
LEFT JOIN patient p ON so1.patient_id = p.id;
```

### 3. 服务层

#### SensitiveOperationService.java

##### 方法1: checkAndRecordSensitiveOperation(patientId, scheduleRecordId)
**功能**：检查退号是否为敏感操作，如果是则自动记录

**实现逻辑**：
```java
// 1. 获取挂号记录（含就诊时间）
RegistrationVo registration = registrationMapper.findRegistrationByPatientAndSchedule(...);

// 2. 计算敏感时间窗口
LocalDateTime appointmentStart = registration.getRegistrationDate().atTime(...);
LocalDateTime sensitiveStart = appointmentStart.minusHours(3);
LocalDateTime sensitiveEnd = appointmentStart.plusHours(4);

// 3. 判断当前时间是否在窗口内
boolean isSensitive = now.isAfter(sensitiveStart) && now.isBefore(sensitiveEnd);

// 4. 如果是敏感操作，自动记录
if (isSensitive) {
    recordSensitiveOperation(patientId, "就诊前3小时内退号", remark);
}
```

##### 方法2: recordSensitiveOperation(patientId, opType, remark)
**功能**：记录敏感操作，统一更新倒计时，检查是否触发黑名单

**实现逻辑**：
```java
// 1. 插入新的敏感操作记录
SensitiveOperation operation = new SensitiveOperation();
operation.setOpTime(now);
sensitiveOperationMapper.insert(operation);

// 2. 统一更新该患者所有敏感操作时间（重置倒计时）
sensitiveOperationMapper.updateAllOpTimeByPatientId(patientId, now);

// 3. 统计总次数，判断是否达到3次
int count = sensitiveOperationMapper.countByPatientId(patientId);
if (count >= 3) {
    addToBlacklist(patientId, now);
}
```

##### 方法3: addToBlacklist(patientId, latestOpTime)
**功能**：将患者加入黑名单

**实现逻辑**：
```java
// 1. 检查是否已在黑名单中
if (blacklistMapper.isInBlacklist(patientId) > 0) {
    return;
}

// 2. 获取最近3条敏感操作ID
List<String> senIds = sensitiveOperationMapper.findTop3IdsByPatientId(patientId);

// 3. 创建黑名单记录
Blacklist blacklist = new Blacklist();
blacklist.setSenId1(senIds.get(0));
blacklist.setSenId2(senIds.get(1));
blacklist.setSenId3(senIds.get(2));
blacklistMapper.insert(blacklist);
```

##### 方法4: checkBlacklist(patientId)
**功能**：检查患者是否在黑名单中，返回解除时间

**返回值**：`BlacklistCheckResult`
- `inBlacklist`: 是否在黑名单中
- `releaseTime`: 黑名单解除时间（最新操作时间 + 20天）

```java
public BlacklistCheckResult checkBlacklist(String patientId) {
    if (blacklistMapper.isInBlacklist(patientId) > 0) {
        SensitiveOperation latestOp = sensitiveOperationMapper.findLatestByPatientId(patientId);
        LocalDateTime releaseTime = latestOp.getOpTime().plusDays(20);
        return new BlacklistCheckResult(true, releaseTime);
    }
    return new BlacklistCheckResult(false, null);
}
```

##### 方法5: cleanupExpiredRecords()
**功能**：定时清理超过20天的记录

**实现逻辑**：
```java
LocalDateTime expireTime = LocalDateTime.now().minusDays(20);

// 1. 查找所有过期的患者ID
List<String> expiredPatientIds = sensitiveOperationMapper.findExpiredPatientIds(expireTime);

for (String patientId : expiredPatientIds) {
    // 2. 检查最新操作是否已过期
    SensitiveOperation latestOp = sensitiveOperationMapper.findLatestByPatientId(patientId);
    if (latestOp.getOpTime().isBefore(expireTime)) {
        // 3. 删除黑名单记录
        blacklistMapper.deleteByPatientId(patientId);
        // 4. 删除敏感操作记录
        sensitiveOperationMapper.deleteByPatientId(patientId);
    }
}
```

## 五、业务流程图

### 1. 敏感操作检测流程
```
患者退号
    ↓
获取挂号记录（就诊时间）
    ↓
计算敏感时间窗口：[就诊开始-3h, 就诊结束]
    ↓
判断当前时间是否在窗口内？
    ├─ 是 → 记录敏感操作
    │        ↓
    │      更新所有历史记录时间（统一倒计时）
    │        ↓
    │      统计总次数 ≥ 3？
    │        ├─ 是 → 加入黑名单
    │        └─ 否 → 结束
    └─ 否 → 正常退号
```

### 2. 黑名单拦截流程
```
患者发起操作（挂号/候补/加号）
    ↓
查询黑名单表
    ↓
患者在黑名单中？
    ├─ 是 → 获取最新操作时间
    │        ↓
    │      计算解除时间（+20天）
    │        ↓
    │      抛出异常："您已被加入黑名单，解除时间: YYYY年MM月DD日"
    └─ 否 → 允许操作
```

### 3. 定时清理流程
```
每天00:00执行
    ↓
计算过期时间（当前时间-20天）
    ↓
查找所有过期患者ID
    ↓
遍历每个患者
    ↓
检查最新操作是否已过期？
    ├─ 是 → 删除黑名单记录
    │        ↓
    │      删除所有敏感操作记录
    │        ↓
    │      日志记录
    └─ 否 → 跳过
```

## 六、关键技术点

### 1. 统一倒计时实现
```sql
-- updateAllOpTimeByPatientId 方法的SQL
UPDATE sensitive_operation 
SET op_time = #{newTime} 
WHERE patient_id = #{patientId}
```
**原理**：每次产生新的敏感操作时，将该患者所有历史记录的 `op_time` 更新为当前时间，实现"20天倒计时重新计算"的效果。

### 2. 就诊时间计算
```java
// 根据时段名称计算就诊开始时间
LocalDateTime appointmentStart = registration.getRegistrationDate().atTime(
    LocalTime.parse(registration.getTimePeriodName().contains("上午") ? "08:00:00" : "13:30:00")
);

// 假设每个时段持续4小时
LocalDateTime appointmentEnd = appointmentStart.plusHours(4);

// 敏感时间窗口：就诊开始前3小时到就诊结束
LocalDateTime sensitiveStart = appointmentStart.minusHours(3);
LocalDateTime sensitiveEnd = appointmentEnd;
```

### 3. ID自动生成
```sql
-- 生成下一个敏感操作ID
SELECT COALESCE(MAX(CAST(SUBSTRING(id, 4) AS INTEGER)), 0) + 1 AS next_num 
FROM sensitive_operation

-- 生成下一个黑名单ID
SELECT COALESCE(MAX(CAST(SUBSTRING(id, 3) AS INTEGER)), 0) + 1 AS next_num 
FROM blacklist
```

**Java 侧格式化**：
```java
String senId = String.format("SEN%04d", nextNum);   // SEN0001
String blacklistId = String.format("BL%04d", nextNum);  // BL0001
```

## 九、注意事项

### 1. 时间同步问题
- 确保应用服务器、数据库服务器时间一致
- 建议使用 NTP 同步

### 2. 并发控制
- `recordSensitiveOperation` 方法使用 `@Transactional` 保证原子性
- `updateAllOpTimeByPatientId` 可能存在性能瓶颈（单患者多条记录更新）

### 3. 性能优化建议
- 为 `patient_id` 和 `op_time` 字段建立索引（已实现）
- 定时任务避免在高峰期执行（当前设置为凌晨00:00）

### 4. 日志监控
关键操作已添加日志：
- 敏感操作记录：`log.warn("检测到敏感操作: ...")`
- 黑名单触发：`log.warn("患者{}已加入黑名单...")`
- 权限拦截：通过异常消息传递给前端
- 定时清理：`log.info("清理完成: ...")`
